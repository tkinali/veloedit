# VeloEdit — Mimari

Milisaniye hızında açılan, hafif, GPU ivmelendirmeli, çok görünümlü (metin / hex / görsel) editör.
Hedef: Fedora (x86_64-unknown-linux-gnu); Ubuntu ve diğer dağıtımlarda aynı kodla derlenir (henüz yalnızca Fedora'da doğrulandı).

Durum: **M1** (iskelet), **M2** (watcher, Ctrl+P, komut paleti, tree-sitter, temalar/ayarlar), **M3** (özel editör çekirdeği: rope, undo/redo, satır numarası, minimap, git gutter, yatay kaydırma) ve **M4'ün editör kısmı** (çoklu imleç, bul/değiştir, imleç yanıp sönmesi, parantez eşleştirme) tamam. **M5** (proje genelinde arama, satır kaydırma, hex düzenleme, ayarlar paneli) ve **M6** (arama paneli yeniden tasarımı, kaydırma çubukları, menü çubuğu + sağ tık menüsü, dosya işlemleri, Ctrl+O, çok daha fazla dil) ve M6 ek turu (editör sağ tık menüsü, Twig/Jinja, yan çubuk boyutlandırma, Markdown önizleme) tamam. Kalanlar §9'da.

## 3. Çalışma zamanı mimarisi

```
                ┌──────────────────── UI thread (iced event loop) ────────────────────┐
 klavye/fare ──▶│  Message ──▶ App::update(&mut self) ──▶ Task<Message>               │
 window events  │                   │                          │                      │
 Subscriptions ─▶                   ▼                          │ (asenkron iş)        │
  · keyboard    │            App state: Workspace, TabSet,     │                      │
  · watcher     │            Palette, Settings, dialog         │                      │
  · timers      │                   │                          │                      │
                │                   ▼                          │                      │
                │            App::view(&self) ──▶ ui::* ──▶ GPU│(wgpu)                │
                └───────────────────────────────────────────── │ ─────────────────────┘
                                                               ▼
                         ┌────────────── worker thread'ler (tokio/thread-pool) ──────────────┐
                         │ loader::open     detect (ilk 8 KiB) → text | image decode | hex    │
                         │ workspace::read_dir / palette::index::build (ignore walk)          │
                         │ palette::rank_files  (nucleo, sorgu başına, eski sonuçlar atılır)  │
                         │ syntax::highlight    (artımlı tree-sitter parse + span)            │
                         │ Snapshot::write · atomic_write · settings::set                     │
                         └────────────────────────────────────────────────────────────────────┘
```

Kurallar:
* **UI thread'de, süresiz bekleyebilecek disk G/Ç yok** (ağ bağlantılı bir dosya sistemi cevap vermeyi bırakırsa `stat`/`read` dakikalarca ya da sonsuza dek bloklanır). Yerel, küçük dosyalar (`session.json`, `settings.json`) senkron okunur; kullanıcının dosyalarına/klasörlerine her soru `fsx::is_dir/is_file/canonical` ile **300 ms süre sınırıyla** sorulur (cevap yoksa `None` = bilinmiyor), okuma/yazma/listeleme `fsx::off_thread` ile kendi iş parçacığında çalışır (bkz. "Ağ bağlantılı dosya sistemleri" aşağıda).
* `update()` ağır iş yapmaz; `Task::perform` ile worker'a devreder, sonuç yeni bir `Message` olarak döner.
* Widget operasyonları (`focus`, `scroll_to`) iced 0.14'te `update`'ten **sonra, UI yeniden kurulduktan sonra** çalışır — bu yüzden yeni oluşan widget'a odaklanmak/kaydırmak güvenlidir (`App::settle()`).
* Clone olmayan büyük yükler `Handoff<T>` (al-bir-kez kutusu) ile mesajda taşınır.

## 4. Dosya tespiti (`detect.rs`)

(1) **Güçlü magic** (PNG/JPEG/GIF/WebP) → Image; (2) **zayıf magic** (BMP/ICO) yalnızca uzantı `image/*` ise; (3) NUL → Binary; (4) geçersiz UTF-8 → Binary (kaydederken bozmamak için); (5) kontrol karakteri oranı > %10 → Binary; (6) aksi halde Text. SVG metin kalır. Boyut > 16 MiB metin → lazy hex görünümü.
İlk **8 KiB** okunur (isteğin 1024'ü yerine: UTF-8/kontrol analizi daha güvenilir, maliyet aynı — `SNIFF_LEN`).

## 5. Hex görünümü

* Bellekte yalnızca `BUF_ROWS` (120) satır; `read_at` ile sadece görünen pencere okunur (1 GiB testli).
* Sanal kaydırma yüksekliği **8 000 000 px ile sınırlı** (f32 tam sayı kesinliği). Daha büyük dosyalarda kaydırma çubuğu konumu dosyaya orantılı eşlenir (çubuğun ortası = dosyanın ortası).
* `scrollable` kendi ofsetini tuttuğu için sekme/yan panel değişince `App::settle()` modeli `scroll_to` ile yeniden eşitler.

## 6. Oturum kurtarma (hot exit)

`~/.local/state/veloedit/` (`$VELOEDIT_STATE_DIR`): `session.json` (sekmeler, kökler, açık dizinler, aktif sekme) + `drafts/draft-<id>.txt` (kaydedilmemiş tamponlar).
Değişiklikten 1,5 sn sonra ve pencere kapanırken yazılır; kapatma **sormaz**, tek bir kirli sekmeyi kapatmak sorar. Sıra: yeni draft'lar → `session.json` → referanssız draft'ları sil; hepsi tmp+rename ile atomik. Draft'lar `~/.cache` yerine state dizininde (cache temizleyicileri silebilir).

## 7. Disk izleme (M2)

* **Ne izlenir:** genişletilmiş + yüklenmiş sidebar dizinleri ve açık dosyaların üst dizinleri; hepsi **özyinelemesiz**. Watch sayısı ekranda görünenle orantılı (`node_modules`/`target` için binlerce inotify watch'ı yok). İzleme kümesi değişince abonelik yeniden başlar (`WatchSet` kimlik olarak hash'lenir).
* **Debounce:** 150 ms sessizlikten sonra tek bir toplu `FsChanged(paths)`. `Access` olayları yok sayılır (kendi okumalarımız geri besleme yaratmasın).
* **Sidebar:** etkilenen dizin yeniden taranır; `Workspace::set_children` mevcut düğümleri **birleştirir** (açık alt dizinler/yüklenmiş alt ağaçlar korunur). Dizin her genişletildiğinde yeniden taranır (kapalıyken izlenmediği için).
* **Açık belgeler:** değişen dosya yeniden okunur ve içerik **hash'i** `TextDoc::disk_hash` ile karşılaştırılır → kendi kaydımız (aynı hash) yok sayılır. Temiz tampon sessizce yeniden yüklenir; **kirli tampon asla ezilmez**: sekmede `!` işareti + durum çubuğu uyarısı, kaydetmek **Overwrite / Reload / Cancel** sorar. Silinen dosya bildirilir, sekme açık kalır. Hex/görsel sekmeleri yeniden açılır.

## 8. Palet, arama, ayarlar, temalar, sözdizimi (M2)

**Ctrl+P (dosya):** workspace kökleri `ignore` ile yürünüp dizine alınır (worker, ≤200k dosya, `.gitignore` uygulanır); dizin FS olayında bayatlar, palet açılınca yenilenir. Her tuş vuruşunda `nucleo` sıralaması worker'da çalışır; sorgu kimliği (`palette_seq`) ile gecikmiş sonuçlar atılır. Boş sorguda açık sekmeler önce gelir. Smart-case, yol bonusu, eşitlikte kısa yol.
**Ctrl+Shift+P (komutlar):** `Command` enum'u → `Message`; temalar `theme::ALL`'dan üretilir. Palet/diyalog açıkken editör **hiçbir tuşa tepki vermez** (`modal` bayrağı), Esc/oklar `event::listen_with` ile odaklı `text_input` yutsa bile yakalanır.
**Ayarlar:** `~/.config/veloedit/settings.json` (`$VELOEDIT_CONFIG_DIR`): `theme` (`dark`|`light`), `font_size`, `tab_size`. Eksik anahtar → varsayılan; **geçersiz JSON → durum çubuğunda hata** (sessizce yok sayılmaz). Palet komutları (`Theme: Light`, `Increase Font Size`) tek anahtarı okuyup-değiştirip-yazar, **diğer anahtarlar korunur**. "Preferences: Open Settings" dosyayı sekmede açar; kaydedince canlı uygulanır.
**Tema:** `ui::theme::Colors` (UI + sözdizimi renkleri). Şema her view fonksiyonuna parametre olarak geçer; global durum yok.
**Sözdizimi:** `text → (artımlı parse) → tree → highlights.scm yakalamaları → bayt başına sınıf haritası (sonraki yakalama kazanır) → satır başına span`. iced'in `Highlighter` arayüzü satır satır çalıştığı için parse işi worker'da yapılır, `TsHighlighter` yalnızca hazır `Arc<LineSpans>`'ten satırın span'lerini **arar**; ayarların eşitliği `Arc` işaretçi kimliğiyle, yeni parse/tema → yeniden boyama. Düzenleme sonrası ~90 ms debounce, önceki ağaç `InputEdit` (ortak önek/sonek farkı) ile yeniden kullanılır; **artımlı sonuç = tam parse sonucu** testle doğrulanır. Eski span'ler bir düzenleme geride kalabilir; satır uzunluğu/UTF-8 sınırlarına kırpılır. Diller: Rust, Python, JS/JSX, TS/TSX, JSON, TOML, Bash, C, HTML, CSS, YAML, Go. 2 MiB üstü dosyalar renklendirilmez.

## 8b. Editör çekirdeği ve widget (M3)

**Katmanlar:** `EditorState` (saf mantık) ← `Action` ← `EditorView` (widget, girdiyi `Action`'a çevirir ve çizer). Widget belge durumu tutmaz; `&EditorState` okur, fare/klavyeyi `Action` olarak yayınlar, uygulama `update()`'te uygular (Elm). Widget'ın yalnızca *düzen sırasında* bilebildiği şeyler (karakter genişliği, görünüm boyutu) `EditorState::metrics` içindeki bir `Cell`'e yazılır; sayfa kaydırma, "imleci görünür tut" ve kaydırma sınırları bunu kullanır.
**Tampon:** `ropey::Rope`; imleç/seçim karakter indeksi; dikey harekette istenen *görüntü sütunu* korunur (tab = sekme durağı, CJK = 2 sütun). CRLF dosyaları CRLF olarak kalır (Enter/yapıştırma belgenin satır sonunu kullanır; `\r\n` çiftinin ortasında durulmaz).
**Undo/redo:** düzenleme listesi (konum, silinen, eklenen, önceki/sonraki seçim). Ardışık yazma (kelime kelime, 1 sn pencere), Backspace ve Delete dizileri tek adımda birleşir; kaydetme noktasında birleşme kesilir. **Kirli durumu geçmişten türetilir:** kaydedilmiş noktaya geri alınca sekme tekrar temiz olur; kayıttan önceki bir noktaya gidip yeni düzenleme yapılırsa o durum erişilemez sayılır.
**Girdi:** tıklama/çift/üçlü tıklama (kelime/satır), gutter'a tıklama satırı seçer, sürükleme, Shift+tıklama, tekerlek (Shift = yatay), Ctrl+Z/Y/Shift+Z/A/C/X/V, Ctrl+←/→/Backspace/Delete (kelime), Home (akıllı: ilk boşluk-olmayan → sütun 0), PgUp/PgDn, Tab/Shift+Tab (seçili satırları girintiler; **seçimi asla silmez**), Enter'da otomatik girinti (`{ [ ( :` sonrası bir kademe). Uygulama kısayolları (Ctrl+S/P/B/W/N/Tab…) widget tarafından yutulmaz. Palet/diyalog açıkken (`modal`) editör hiçbir girdiye tepki vermez.
**Çizim:** yalnızca görünen satırlar; her satır tree-sitter span'lerinden renkli "run"lara bölünür (boşluk-only run çizilmez), 10 000 sütundan ötesi çizilmez/vurulmaz. Katmanlar: metin alanı (geçerli satır, seçim, glifler, imleç) → gutter (git işaretleri + satır no) → minimap → yatay kaydırma ipucu.
**Minimap:** 1 px/sütun, 2 px/satır, span renkleriyle; dosya minimap yüksekliğinden uzunsa minimap kaydırmayla orantılı kayar (Sublime gibi); tıklama/sürükleme editörü kaydırır; görünen bölge yarı saydam kutu.
**Git gutter:** sol kenarda sarı = değişmiş, yeşil = eklenmiş, kırmızı çizgi = üstünden satır silinmiş. Açılışta `HEAD` içeriği bir kez alınır (worker), sonra her düzenlemeden ~90 ms sonra tamponun `HEAD`'e satır diff'i çıkarılır (CRLF/LF farkı sayılmaz). Takip edilmeyen dosya/git yoksa işaret yok. "Git: Refresh Gutter" komutu `HEAD`'i yeniden okur (dışarıda commit sonrası).

## 8c. Çoklu imleç, bul/değiştir (M4)

**Çoklu imleç.** `EditorState` artık sıralı, ayrık bir imleç listesi tutar (+ bir *birincil*; görünüm onu izler). Her metin değişikliği bir **işlem**dir: imleç başına bir `Piece` (değişiklik öncesi koordinatlarda konum, silinen, eklenen); parçalar sondan başa uygulanır, böylece öndekilerin indeksleri kaymaz. Geri alma işlem-sonrası koordinatları kayma toplamıyla bulur ve tersini uygular; **tek işlem = tek undo adımı** (3 imlece 3 harf yazmak tek adımda geri alınır). Ardışık yazma/Backspace/Delete aynı imleç sayısıyla birleşir. Çakışan/dokunan imleçler her işlemden sonra birleştirilir (`normalize`); bir silme komşu imlecin bölgesine taşamaz (`lo..hi` kıskacı).
Girdi: `Ctrl+tık` imleç ekler, `Ctrl+D` (önce kelimeyi seçer, sonra sıradaki eşleşmeyi ekler; sona gelince başa sarar), `Ctrl+Alt+↑/↓` (ilk/son imlecin üstüne/altına, sütunu hatırlar), `Esc` tek imlece döner. Kopyalama seçimleri satır sonuyla birleştirir; N imlece N satır yapıştırınca her imlece bir satır gider. Girinti/çıkıntı seçili satırların birleşimine **bir kez** uygulanır; seçimler parçalardan geçirilerek (başlangıç sol, bitiş sağ çekim) taşınır.
**Doğrulama:** saf mantık `state_tests.rs` içinde; ayrıca rastgele işlem testi (`VELOEDIT_FUZZ=6000 cargo test random_operations`: 6000 oturum × 250 rastgele eylem — çoklu imleç, CRLF, çok baytlı karakter — her adımda "sıralı, ayrık, metin sınırı içinde" değişmezleri; sonda *tümünü geri al = orijinal*, *tümünü yinele = uç nokta*). Bu test bir hata yakaladı (Ctrl+D sonrası içerideki imleç birleşmiyordu), düzeltildi.

**Bul / değiştir** (`Ctrl+F`, `Ctrl+H`, `F3`/`Shift+F3`, `Esc`). Her sorgu (düz ya da regex) `regex` kütüphanesinden geçer (düz metin kaçışlanır): büyük/küçük harf, `\b` tam kelime, `$1` şablonları iki kipte de aynı davranır; `^`/`$` satır başı/sonu; boş eşleşen desen (`x*`) hata olarak bildirilir. Aramalar worker'da, sonuçlar `(sorgu, sekme, sürüm)` anahtarıyla etiketlenir: düzenleme sonrası eski sonuçlar **çizilmez ve kullanılmaz** (≈90 ms içinde yeniden aranır). Yazdıkça artımlı arama seçim başlangıcından ilk eşleşmeye atlar; ileri/geri sarar; durum "3 of 12" / "No results" / regex hatası. *Replace* seçili eşleşmeyi değiştirip sonrakine geçer; *Replace All* tüm belgeyi regex ile değiştirip **en küçük tek düzenlemeye** indirger (**tek undo adımı**, çok baytlı karakterlerde sınır güvenli). Eşleşmeler editörde vurgulanır (geçerli olan daha parlak).
**Küçük ayrıntılar:** imleç, her girdiden sonra sabit, sonra 530 ms'de bir yanıp söner (yeniden çizim yalnızca geçiş anında istenir, boşta CPU harcamaz); imleç parantezin yanındayken eşleşen çifti çerçevelenir (50 000 karakterle sınırlı tarama; string/yorum yok sayılmaz); kopya-yapıştır, kaydedilmiş bir taslağın diskle aynı olduğu durumda (kullanıcı yazıp geri sildi) sekme artık "kirli" gelmez.

## 8d. Proje araması, hex düzenleme, satır kaydırma, ayarlar (M5)

**Proje genelinde arama** (`Ctrl+Shift+F`). Palet katmanının üçüncü kipi: sorgu + `Aa`/`\b`/`.*` düğmeleri, altında "N results in M files". Worker'da `ignore` ile yürünür (`.gitignore`/gizli klasör kuralları, `.git` hariç), yalnızca metin dosyaları (`detect::classify`), >2 MiB atlanır, en çok 2000 isabet. Her sorgu değişiminde önceki arama **iptal edilir** (paylaşılan nesil sayacı; worker her dosyada bakar). Enter/tık dosyayı açıp eşleşmeyi seçer (`OpenAt`; dosya henüz yüklenmediyse konum yüklenince uygulanır). Önizleme uzun satırlarda eşleşmeye ortalanır. Aynı palette `Ctrl+G` / `:42` ile satıra, hex sekmesinde `:0x1F40` ile bayt ofsetine gidilir. Açık ama kaydedilmemiş tamponlar değil, **diskteki** içerik aranır.

**Hex düzenleyici** (özel widget `ui/hex_view.rs` + saf model `editor/hex.rs`). Eski `scrollable` + 8 000 000 px sanal yükseklik hilesinin yerine kendi satır tabanlı kaydırması (`f64` satır indeksi, tam kesin; kaydırma çubuğu orantılı) geldi. Üzerine yazma kipi: dosya boyutu değişmez. Düzenlemeler küçük bir kaplama (`BTreeMap<ofset, bayt>`) içinde durur — 1 GiB dosyada 3 bayt = 3 kayıt. Hex alanında hex rakamı (önce yüksek, sonra düşük yarım bayt; iki yarım **tek undo adımı**), ASCII alanında yazdırılabilir karakter; `Tab` alan değiştirir; oklar/PgUp/PgDn/Home/End/Ctrl+Home/End, tık ile bayt seçimi; `Ctrl+Z/Y`. Değiştirilen baytlar tema "dirty" renginde; bir değer dosyadakiyle aynıysa düzenleme düşer (kirli sayılmaz). `Ctrl+S` düzenlemeleri **yerinde yama** olarak yazar (bitişik baytlar tek `write_at`, sonra `sync_all`), yazma bitince dosya izleyicisinin yankısı (`recently_saved`) yok sayılır. Sekme kapatılırken kirli hex sekmesi için Kaydet/Kaydetme/İptal sorulur; oturum kaydı bekleyen düzenlemeleri (`hex_edits`) saklar, yeniden açılışta dosya boyutu aynıysa geri yüklenir; dosya dışarıdan değişirse düzenlemeler korunur ve uyarı verilir. **Sınır:** yerinde yazma atomik değildir (yazma sırasında çökme/elektrik kesintisi yamayı yarım bırakabilir).

**Satır kaydırma** (ayar: `word_wrap`). Monospace olduğu için kaydırma, metin ve sütun sayısının saf bir fonksiyonu: satır, kenara sığmayan ilk karakterde son boşluktan bölünür (boşluklar kenardan taşabilir); boşluksuz uzun kelime kenarda sert kesilir. Görüntü sütunları satır başından ölçülmeye devam eder (tab durakları, tıklama ve kaydırmasız kod yolları aynı kalır), bir parça yalnızca başladığı sütunu bilir. `EditorState` tek bir **görsel satır API'si** sunar (`total_rows`, `row_span`, `row_of`, `idx_at_row_col`, `selections_in_row`, `carets_in_rows`); kaydırma kapalıyken her satır bir görsel satırdır, bu yüzden widget iki kipte de aynı kodla çizer. Dikey hareket/PgUp/PgDn görsel satırlarla çalışır ve sütunu hatırlar; imleç görünür tutma ve kaydırma sınırları görsel satırlara göredir; yatay kaydırma kapanır. Satır numarası yalnızca ilk parçada, git işareti satırın tüm parçalarında. Satır tablosu her düzenlemede baştan kurulur, bu yüzden **600 000 karakterden büyük belgelerde kaydırma kendiliğinden kapanır**.

**Ayarlar paneli** (`Ctrl+,`, palet: "Preferences: Settings..."): tema, yazı boyutu, sekme boyutu, satır kaydırma, minimap, kaydederken sondaki boşlukları kırpma ("Trim on save") — hepsi anında uygulanır ve `settings.json`'a tek anahtar olarak yazılır (diğer anahtarlar korunur). Minimap kapalıyken metin alanı genişler.

## 8e. Arama paneli, kaydırma çubukları, menüler, dosya işlemleri, diller (M6)

**Projede Ara paneli** (`ui/search_panel.rs`; durum hâlâ `Palette{mode: Search}`). Sonuçlar *dosyaya göre gruplanır* (dosya adı kalın + klasör silik + isabet sayısı), her isabet satır numarası + tek satıra kırpılmış (`clip`, sarma yok) monospace önizleme olarak gelir ve eşleşen kısım vurgu renginde boyanır (`Hit.mark`). Liste gerçek bir `scrollable` + `virtual_list` penceresidir (2000 isabette de ~120 satır kurulur); ↑/↓/PgUp/PgDn seçimi sürer ve seçili satırı görünür tutar (`scroll_to`). Sonuçlar yola göre sıralıdır (`sort_by_file_path`). İkinci giriş **Files** filtresidir: `*.php, *.js` yalnızca bunları, `!vendor` / `-vendor` bunu hariç tutar (`ignore::overrides`; boş = hepsi). **Kapsam** (`In:`): "all folders" ya da tek bir klasör (`Choose…` ya da yan çubukta sağ tık → *Find in Folder…*); Sublime'ın "Where" alanının karşılığı. `Tab`/`Shift+Tab` iki giriş arasında geçer. Filtre oturum içinde hatırlanır.

**Kaydırma çubukları.** Editörde sağ kenarda her zaman ayrılmış 12 px'lik dikey çubuk (minimap onun soluna oturur; ayrılmış olması şart, çünkü içeriğe bağlı olsaydı satır kaydırma genişliği ↔ çubuk varlığı döngüsü oluşurdu) ve içerik taşınca altta yatay çubuk. İkisi de sürüklenir; boşluğa tıklamak başparmağı oraya ortalar. Tuş: `Action::ScrollTo{y}` / `ScrollToX{x}`. Yatay çubuk içerik genişliğini görünen satırlardan *tahmin eder* (kaydırdıkça büyür). Hex görünümündeki çubuk aynı stile getirildi.

**Menü çubuğu ve menüler.** Pencerenin üstünde File · Edit · View · Go · Preferences · Help; her biri `ui/menu.rs`'in `Entry` listesinden çizilen bir kart (kısayol ipucu, onay işareti, devre dışı hâl). Bir menü açıkken diğer başlığın üstüne gelmek menüyü değiştirir (`on_enter`), tıklama dışı bir yere basmak kapatır; açılır katman menü çubuğunun *altından* başlar ki çubuk tıklanabilir kalsın. Girdiler uygulamanın durumuna bağlıdır (Kaydet yalnızca sekme varken, Kes/Kopyala/Yapıştır yalnızca metin sekmesinde, View'daki onaylar ayarlardan). `View → Menu Bar` ya da `settings.json: "menu_bar": false` çubuğu gizler. Her seçim `MenuPick(Box<Message>)` ile gelir: menüyü kapatır, komutu çalıştırır, odağı editöre geri verir.

**Yan çubuk sağ tık menüsü.** Satır başına `mouse_area::on_right_press`. Konum için `iced` sağ tık olayında imleç noktasını vermediğinden, **hiçbir mesaj üretmeyen** bir abonelik her `CursorMoved`'da imleç konumunu bir `AtomicU64`'e yazar (mesaj üretseydi her piksel hareketinde yeniden çizilirdi). Klasör: Yeni Dosya/Klasör, Klasörde Ara, Yeniden Adlandır, Çöpe Taşı, yol kopyala (mutlak/göreli), Dosya Yöneticisinde Göster (`xdg-open`), Yenile; kök: ayrıca "Remove Folder from Workspace".

**Dosya işlemleri** (`fileops.rs`, worker'da). Ad girişi bir modal komut isteminden (`Prompt`) gelir; ad `Component::Normal` dışında bir şey içeremez (`..`, `/etc/x`, boş ad reddedilir), var olan dosya ezilmez, yeniden adlandırma aynı klasörde kalır. *Silme yok, çöpe taşıma var* (`trash` crate'i, freedesktop spec) — geri alınabilir. Yeniden adlandırılan dosya bir sekmede açıksa sekmenin yolu/başlığı/dili güncellenir; çöpe taşınan dosyanın *temiz* sekmeleri kapanır, kirli olanlar korunur. Ağaç, izleyici sayesinde kendiliğinden tazelenir (ayrıca açık tarama yapılır).

**Ctrl+O / sürükle-bırak.** `Ctrl+O` herhangi bir dosyayı (çoklu seçim) proje olmadan açar; `Ctrl+Shift+O` hâlâ klasör ekler. Pencereye dosya bırakmak dosyayı açar, klasör bırakmak çalışma alanına ekler. `Ctrl+Q` çıkar (oturum önce kaydedilir).

**Diller.** 25 tree-sitter grameri + tablo tabanlı lexer. Dosya adı/uzantı → dil eşlemesi `Lang::detect`: örn. `.php/.phtml/.inc` PHP, `.blade.php` PHP, `.vue/.svelte/.twig/.tpl/.ejs/.hbs` HTML, `.conf/.env/.gitignore/.ini` INI, `Makefile`, `CMakeLists.txt`, `Gemfile`, `Dockerfile`. **Enjeksiyonlar** (`engine.rs::paint_injections`): başka dilde yazılmış bölgeler yalnızca o aralıklarla (`set_included_ranges`) ikinci bir gramerle ayrıştırılıp ana dilin altına boyanır: PHP'deki `text` → HTML (onun içindeki `<script>` → JS, `<style>` → CSS), HTML'de `<script>`/`<style>`, Markdown'daki `inline` → Markdown-inline. En fazla 2 seviye. **Lexer** (`syntax/lexer.rs`): yorum, string (üçlü tırnak dahil), sayı, anahtar sözcük (SQL'de büyük/küçük harf duyarsız), `Büyük`→tip, `BÜYÜK_HARF`→sabit, `ad(`→fonksiyon; yeni dil eklemek tabloya bir satır. SQL/C#/C++ bilerek gramer değil lexer: yalnızca SQL grameri ikiliye +13 MB katıyordu.

**M6 ek turu (ilk kullanım geri bildirimi).**

*Editör sağ tık menüsü.* `text_view` editörü `mouse_area` ile sarar; widget sağ tıkta yalnızca imleci tıklanan yere taşır (tıklanan yer bir seçimin içindeyse seçim korunur: `EditorState::point_in_selection`) ve olayı **yakalamaz**, böylece sarmalayıcı `EditorContext` mesajını üretir. Menü: Kes/Kopyala (seçim yoksa pasif), Yapıştır, Tümünü Seç, Geri Al/Yinele, Bul/Değiştir, "Find (Selection) in Files…", Satıra Git, dosya yolu kopyala, dosya yöneticisinde göster. Menü kartı yan çubuk menüsüyle ortaktır (`ui/menu.rs`).

*Twig / Jinja / Nunjucks / Liquid* (`.twig .j2 .jinja .jinja2 .njk .liquid`). crates.io'da Twig grameri yok; bu yüzden `Lang::Twig` = **HTML grameri + şablon kaplaması** (`lexer::paint_template`). Önce HTML (ve içindeki `<script>`/`<style>`) boyanır, sonra `{# yorum #}`, `{{ ifade }}` ve `{% deyim %}` bölgeleri HTML'in boyasını silip yeniden boyar: ayraçlar (`{{-`, `-}}`, `{%~` dahil), anahtar sözcükler (`for in if endfor block extends ...`), string, sayı, `|filtre` (fonksiyon rengi), `.özellik`, `ad(` çağrıları. String içindeki `}}` etiketi bitirmez; kapanmamış bir `{{` en çok 4000 bayt ileriye bakar, yani yazarken dosyanın geri kalanını boyamaz. Blade (`.blade.php`) hâlâ PHP gramerine gidiyor.

*Yan çubuk.* Genişlik sürüklenir (5 px'lik tutamaç, 140-640 px, `session.json`'da saklanır); sürüklerken yalnızca o süre için bir fare aboneliği çalışır, normalde sıfır maliyet. Satırların sağında 12 px boşluk bırakılır, böylece kaydırma çubuğu `×` düğmelerinin üstüne binmez.

*Markdown önizleme.* `.md` dosyaları sol kaynak / sağ derlenmiş görünümle açılır (`View → Markdown Preview`, palet: "Toggle Markdown Preview", ayar `markdown_preview`). Derleme iced'in `markdown` widget'ı (pulldown-cmark) ile yapılır; ayrıştırılmış öğeler `TextDoc.preview` içinde sürümle birlikte tutulur ve `App::update` her mesajdan sonra sürüm gerideyse yeniden ayrıştırır (`view()` içinde değil: view her olayda çalışır). Önizleme kaynağın göreli kaydırma konumunu izler (`snap_to`). Bağlantılar: `http(s)/mailto` masaüstüne (`xdg-open`), göreli bağlantılar belgenin yanındaki dosyayı sekmede açar. **Büyük belgeler.** Ölçüm (sentetik, yoğun bir belge; `markdown::parse` + iced yerleşimi): 400 KiB = 40 ms ayrıştırma + ~250 ms yerleşim, 1 MiB = 185 ms + ~490 ms, 4 MiB = 2,8 s + ~1,9 s, 16 MiB = 102 s ayrıştırma (süper-doğrusal). Yerleşim **her güncellemede** blok sayısıyla orantılı çalıştığı için eski "400 KiB üstü kapalı" sınırı vardı; artık `editor/preview.rs`: ≤48 KiB belge bütün gösterilir; daha büyüğü **bloğu bölmeden** (boş satırdan sonra, kod çitleri dışında) ~16 KiB'lık parçalara ayrılır ve yalnızca editörün üst satırının bulunduğu parça ile iki komşusu ayrıştırılıp gösterilir (≈ birkaç yüz blok). Editör başka bir parçaya kaydırılınca pencere kayar (`Preview::is_current`), önizleme penceredeki göreli konuma `snap_to` yapar ve üstte "showing lines a–b of N" notu görünür. Parça tablosu yalnızca metin değişince O(n) yeniden kurulur (rope satırları üzerinden, tüm metni kopyalamadan). **Sınırlar:** büyük belgede önizleme bağımsız gezilemez, editörü izler (pencere dışına tekerlekle çıkılmaz); parça sınırları listeleri/başvuru-tipi bağlantı tanımlarını (`[x]: url`) bölebilir; resimler yalnızca alt metin kutusu; kod blokları renklendirilmez; kaydırma eşlemesi oransaldır.

*Sekme çubuğu.* Sekmelerin genişliği başlıktan *tahmin edilen sabit bir değerdir* (`tab_bar::tab_width`, 100-240 px; taşan başlık kırpılır); böylece her sekmenin şeritteki konumu hesaplanabilir ve etkin sekme `reveal_active_tab` ile görünür alana kaydırılır (`settle()` içinde; şeridin ilk boyut bildirimi gelince de bir kez). Şerit yatay bir `scrollable`'dır; dikey fare tekerleği yatay kaydırıcıya hiçbir şey yapmaz ve `scrollable` tekerlek olayını *yuttuğu* için `mouse_area::on_scroll` kaydırıcının **içine** konur (dışına konursa hiç tetiklenmez). `TabsWheel(px)` ofseti kenarlarda kıstırır. Sağ uçta `+` ve `▾`: `▾` tüm açık sekmeleri (başlık, kirli noktası, klasör ipucu, etkin olana ✓) açılır menü olarak listeler; liste pencereden uzunsa kaydırılır (`ui/menu.rs` kartı artık genişlik ve azami yükseklik alır).

*Help → About.* Durum çubuğuna tek satır yazmak yerine gerçek bir diyalog (`Dialog::About`): sürüm, platform, kullanılan kütüphaneler, `settings.json` ve oturum klasörünün yolları. `Esc`/Close kapatır.

*Dosya türü etiketleri.* Yan çubukta her dosyanın önünde uzantıya/ada göre renkli kısa bir yazı (`PHP`, `JS`, `MD`, `TWG`, `DKR`...; `ui/file_badge.rs`). Resim/ikon yazı tipi yok: ikili boyutuna, açılış süresine ve belleğe etkisi sıfır; yalnızca görünen (sanallaştırılmış) satırlar için bir `text` daha çizilir. Bilinmeyen uzantı silik olarak gösterilir, uzantısız dosya `·`. Açık temada renkler %28 koyulaştırılır.

*Uygulama simgesi.* `assets/make_icon.py` (görüntü kütüphanesi gerektirmeyen düz Python; SDF + 4×4 süper örnekleme) koyu yuvarlak kare üstüne mavi bir "V" ve bir metin imleci çizer ve `assets/icon-{128,256}.png` üretir. 128 px'lik PNG ikiliye gömülür ve açılışta çözülür (<1 ms) → `window::Settings.icon`; X11'de pencere `_NET_WM_ICON` ve `WM_CLASS=veloedit` alır (görev çubuğu/Alt+Tab). Başlatıcıda/uygulama menüsünde ve Wayland'de simge `.desktop` dosyasından gelir: `packaging/veloedit.desktop` + `packaging/install-desktop.sh` (kullanıcı dizinine kurar, `--uninstall` geri alır; `Exec` gerçek ikili yoluna çevrilir).

*Markdown tabloları ve emoji (bildirilen hata: \"tek satırda, tablo çok kötü\").* iced'in `markdown` widget'ı tabloyu her hücreyi **sarmadan tek satırda** çizip yatay bir `scrollable` içine koyar (ve `Row.cells` özel olduğu için dışarıdan değiştirilemez). Bu yüzden tablolar kaynaktan **kendimiz** ayrıştırılır (`editor/preview.rs::parse_blocks`): belge `Block::Markdown` (iced'e) ve `Block::Table` (kendi) parçalarına bölünür; hücre metni iced'in satır-içi Markdown ayrıştırıcısından geçer (kalın, kod, üstü çizili, bağlantı çalışır). `ui/markdown_view.rs` tabloyu tarayıcı gibi çizer: sütunlar genişliği paylaşır, hücreler sarılır, başlık satırı + zebra + ince çizgiler, hizalama (`:--:`) uygulanır. Sütun genişliği: kısa sütunlar (kimlik, durum; ≤16 karakter) sabit genişlik, uzun metinli sütunlar tipik uzunluklarıyla orantılı `FillPortion` (fill sütunun asgari genişliği olmadığı için kısa sütun asla fill olmaz). **Dar panelde** (metin sütunu başına <120 px) tablo kart düzenine geçer: her satır bir kart, kısa sütunlar başlık satırında, uzun sütunlar kendi başlığının altında - yatay kaydırma yok. Boru işareti kaçışı (`\\|`), eksik hücre doldurma, kod çiti içindeki/alıntı içindeki sahte tabloların atlanması, başvuru-tipi bağlantı tanımlarının her parçaya kopyalanması testlidir. **Dev tablolar:** 500 KB'lık tek tablolu bir belgede boş satır olmadığı için eski parçalayıcı hepsini tek parça sayıyordu; artık satırlar arasından kesilir ve her parça tablonun başlığını (başlık + ayraç satırı) yeniden ekler. **Emoji:** Noto Color Emoji bir COLRv1 yazı tipidir ve iced'in metin çizicisi onu **boş** çizer; önizlemede yaygın durum işaretleri (✅ ❌ ⚠ 🟡 🟢 🔴 🔵 ⭐ ...) emojinin renginde tek renkli simgelere çevrilir (`emoji()`). Editördeki kaynak metinde bu emojiler hâlâ boş görünür (yazı tipi sınırı). **Bölücü:** editör/önizleme ayracı sürüklenir (`preview_frac`, %20-85, oturumla saklanır); panel genişliği `WindowResized` ile izlenen pencere boyutundan hesaplanır.

*Sekme menüsü ve toplu kapatma.* Sekmeye sağ tık: Kapat / Diğerlerini Kapat / Sağdakileri Kapat / Hepsini Kapat, dosya yolu kopyala, dosya yöneticisinde göster, diskten yeniden yükle. Toplu kapatma bir **kuyruk** (`close_queue`) çalıştırır: temiz sekmeler hemen kapanır, kaydedilmemiş olan "Kaydet / Kaydetme / İptal" sorar ve kalanlar cevabı bekler; İptal (ya da Esc) kuyruğun kalanını da bırakır. `close_now` her kapanışta kuyruğu ilerletir (Kaydet → kaydedilince kapanır → devam).

*Markdown kaynak görünümü.* Önizleme açıkken sol (kaynak) yarı **her zaman satır sarar**: dar bir panelde tablo satırları binlerce karakterdir. Genel `word_wrap` ayarı dokunulmadan kalır.

*Tek pencere* (`src/instance.rs`). İlk VeloEdit `$XDG_RUNTIME_DIR/veloedit.sock` Unix soketini dinler (`VELOEDIT_STATE_DIR` varsa onun içinde: geliştirme/test süreçleri gerçek editörle konuşmaz; yol 100 bayttan uzunsa `/tmp` altında yola özgü kısa bir ad kullanılır, çünkü `sun_path` sınırı 108). İkinci başlatma (`veloedit dosya` / dosya yöneticisinde "Birlikte aç") soketten tek satır JSON (`{"open":[mutlak yollar]}`) gönderip hemen çıkar (ölçülen ~4 ms); çalışan pencere dosyaları sekme, klasörleri kenar çubuğu kökü yapar ve öne gelmeyi dener (`gain_focus`; pencere yöneticisi odak çalmayı reddedebilir). Soket 0600'dür, istek 1 MiB ile sınırlıdır. Çökme sonrası kalan bayat soket (kimse yanıtlamıyor) devralınır; soket kurulamazsa tek başına çalışır. **Donmuş pencere de devralınır:** çalışan pencere her isteği, arayüz iş parçacığı onu *işledikten sonra* tek baytla (`k`) onaylar (`Message::External` ardından `Message::Alive`; onay UI thread'inden gelir); isteği gönderen başlatma 1,5 sn içinde onay almazsa o pencereye güvenmez, soket dosyasını silip kendisi pencere olur. (Eskiden istek, hiç bakmayacak bir sürecin soketine "teslim edilip" başlatma sessizce çıkıyordu: ağ bağlantısında donan bir pencere, sonraki tüm başlatmaları yutuyordu.) Onay yerine yalnız bağlantıyı kapatan eski sürümler "canlı" sayılır. Soket dosyasını `cleanup` yalnızca *kendi* (aygıt, inode) kaydıyla eşleşiyorsa siler: geç uyanan eski pencere, yerini alanın soketini silemez. `--new-window` / `-n` ayrı pencere açar. Bu aynı zamanda iki sürecin tek `session.json`'u ezmesini önler.

*Kod katlama* (`editor/state/fold.rs`, her dil için). Blok = açan satırdan sonra **daha derin girintili satırlar** (boş satırlar sayılmaz); Sublime'ın gramersiz diller için yaptığı budur ve süslü parantezli dillerde pratikte aynı sonucu verir. Bloğun hemen ardındaki satır yalnızca bir kapanıştaysa (`}`, `)`, `</div>`, `end`, `fi`...) blokla birlikte katlanır ve `…` işaretinin yanında gösterilir (`function f() { … }`). Katlanmış satırlar, satır kaydırmanın kullandığı **aynı görsel satır tablosuna** "sıfır satır" olarak girer (`with_wrap` artık kaydırma *ya da* katlama varken tablo kurar); kaydırma, tıklama, dikey hareket, minimap kutusu özel durum gerektirmez. Düzenleme katlamaları taşır: üstündeki düzenleme satır numaralarını kaydırır, başlık satırına yazmak katlamayı korur, gizli bölgeye dokunan her şey (değiştir-hepsi dahil) katlamayı açar; undo/redo da aynı yoldan geçer. İmleç/seçim gizli bir satıra düşerse (bul, satıra git, undo) ilgili katlama açılır; bir katlama imleci gizlerse imleç başlık satırının sonuna taşınır. Arayüz: gutter'ın sağ kenarında ok (katlanmışta hep, katlanabilir satırda fare üstündeyken), tıklayınca aç/kapat; `Ctrl+Shift+[` / `]`; palet ve View menüsü: *Fold / Unfold / Fold All / Fold Level 1-3 / Unfold All*. `Fold All` her derinliği, `Fold Level n` yalnızca n. iç içe seviyeyi katlar. Rastgele düzenleme/katlama karışımıyla 25 000 tohumluk soak testi geçti (katlamalar sıralı, metin içinde, imleç gizli satırda değil, satır başına bir görsel satır).

- **Sekme şeridi menü açılınca kayıyordu.** Sebep: her katman (menü, diyalog, palet...) altındakini yeni bir `stack!` içine alıyordu; kök widget'ın türü değişince iced altındaki **tüm widget durumlarını** (sekme/kenar çubuğu kaydırma konumu, editör odağı) atıyordu. Artık `view()` tek düz `stack(layers)` kurar: sayfa her zaman 0. katman, aynı derinlikte. Gerçek pencerede (30 sekme, şerit kaydırılmış) sağ tık menüsü açılıp kapanırken şeridin yerinde kaldığı ekran görüntüsüyle doğrulandı.
- **Katlama oku**: gutter bir karakter genişledi (`GUTTER_EXTRA`), satır numarası sola çekildi, okun tıklama bölgesi 2 karakter (`FOLD_ZONE`), ok yazı boyutunun 1,8 katı ve üzerine gelince bölgeyi gösteren bir kutucuk çıkar. **Katla/aç kısayolu fiziksel köşeli parantez tuşlarına bağlıdır** (`Code::BracketLeft/Right`): Türkçe Q'da bunlar ğ/ü tuşlarıdır; mantıksal "[" Türkçe düzende AltGr+8 gerektirdiği için işe yaramazdı.
- **Ctrl+tık (kenar çubuğu)**: açık klasörde klasörü *ve altındaki her şeyi* kapatır (`Workspace::collapse_recursive`); kapalı klasörde yalnız o klasörü açar. Ctrl durumu `ModifiersChanged` olaylarından izlenir.
- **Pencere durumu** (`session.json: window`): boyut (normal pencerenin), konum, tam ekran. `WindowResized` her seferinde `is_maximized` sorar (tam ekran bir yeniden boyutlandırma olarak görünür); tam ekranken normal boyut/konum korunur. Açılışta `window::Settings` bu değerlerle kurulur; bazı pencere yöneticileri "maximized" ipucunu yok saydığı için açılışta ayrıca `window::maximize` istenir (Cinnamon'da gerçek pencerede böyle çıktı). Kayıtlı konum açılışta `monitor_size` ile denetlenir: ekran dışındaysa pencere ortalanır. Bozuk değerler `WindowState::sane()` ile düzeltilir.
- **Kenar çubuğu adları** sarmaz (`Wrapping::None` + `clip`): sabit yükseklikli satırlarda iki satıra düşen adlar birbirinin üstüne biniyordu; uzun ad kenarda kesilir.
- **Yazı yakınlaştırma**: `Ctrl+=` / `Ctrl++` / `Ctrl+-` / `Ctrl+0` ve `Ctrl+tekerlek` (dokunmatik yüzey kaydırması 30 px'te bir adım). Satır yüksekliği değiştiği için her sekmenin kaydırması aynı oranda ölçeklenir (aynı satırlar üstte kalır). Ayar dosyası yazı boyutu **durulunca** yazılır (tekerlekle saniyede onlarca adım olur). **Klavye düzeni dersi:** Ctrl basılıyken iced `key` olarak *Shift uygulanmamış* karakteri verir (Türkçe Q'da "+" = Ctrl+Shift+"4"); noktalama kısayolları bu yüzden `modified_key`'den okunur. **Numpad dersi:** iced'in `key` alanı `key_without_modifiers()`'tan gelir ve numpad rakam tuşları için NumLock'ın *kapalı* karşılığıdır, **NumLock açıkken de**: KP_0 = `Insert`, KP_1 = `End`, KP_2 = `↓`, KP_3 = `PgDn`, KP_4 = `←`, KP_6 = `→`, KP_7 = `Home`, KP_8 = `↑`, KP_9 = `PgUp`, KP_. = `Delete`; tuşun gerçekte yaptığı işi `modified_key` (ve `text`) söyler. Numpad `0`/`+`/`-` kısayolları bu yüzden *fiziksel* tuştan (`Code::Numpad0/NumpadAdd/NumpadSubtract`) okunur. Aynı yüzden editörde NumLock açıkken numpad rakamları yazmıyor, `End`/`↓`/`←`... gibi davranıyordu (tek `0` yazılıyordu, çünkü `Insert` bir eylem değil): `translate_key` artık numpad rakam/ondalık tuşlarında `ui::effective_key` ile mantıksal tuşa bakar (editör ve hex görünümü; arama/palet kutuları iced `text_input` olduğu için `text`'e baktığından zaten çalışıyordu). NumLock kapalıyken mantıksal tuş da `End`/`↓`... olduğundan gezinme eskisi gibi çalışır. Gerçek pencerede `xdotool` ile doğrulandı (numpad için `xdotool key ctrl+KP_Add` YANLIŞ olaylar üretir; ham keycode kullan: `keydown 37; key 86; keyup 37`, 86=KP_Add, 82=KP_Subtract, 90=KP_0).
- **Ağ bağlantılı dosya sistemleri (SFTP/sshfs/NFS, VPN)** — kullanıcı Nemo'da SFTP yer imiyle (gvfs) bir dosya düzenlerken iki sorun yaşadı; kodda bulunan ve düzeltilen nedenler:
  * *İçerik boşalıp Ctrl+Z çalışmaması.* `disk_changed`, temiz bir buffer'ı diskten okunan *her şeyle* (boş dosya dahil) değiştiriyor ve geçmişi siliyordu (`reset`). Kaydetmenin yankısı (watcher olayı) dosyayı hemen geri okutuyor; bir ağ bağlantısında bu okuma bayat/boş/kesik görünüm döndürebilir (FUSE öznitelik önbelleği, yarım kalan yazma). Sonuç: bellekteki tek sağlam kopya sessizce çöpe gidiyordu. Düzeltmeler: (1) **diskten yeniden yükleme artık geri alınabilir bir düzenleme** (`EditorState::replace_text`: ortak baş ve son korunur, yalnız farklı orta kısım bir `commit` olur; imleç/kaydırma/katlamalar yerinde kalır; `Ctrl+Z` eski metni getirir; 1 Mi karakterden büyük fark geçmişe sığmaz → eski `reset`); (2) **boş okunan dosya sessizce alınmaz**: buffer doluysa korunur, sekme "kaydedilmemiş + çakışma" olur ("… is empty on disk - your text is kept, Ctrl+S writes it back"), Ctrl+S sorar ve "Overwrite" metni geri yazar; kullanıcının kendi "Reload from Disk"i boş dosyayı alır ama yine geri alınabilir; (3) **kendi kaydımızın yankısı geri okunmaz** (`TextDoc::just_saved`: yazma sürerken ve bitişten 2,5 sn sonrasına kadar o sekmenin watcher olayları atlanır).
  * *Bağlantı kopunca pencerenin donması, kapanmaması, sonra hiç açılmaması.* Nedenler: (1) UI thread'inde `is_dir`/`exists`/`canonicalize` (açılışta oturumdaki kökler ve argümanlar, her disk olayında `exists`, Ctrl+O'nun başlangıç klasörü, sürükle-bırak, bağlantı açma) — ölü bir bağlantıda bunlar sonsuza dek bloklanır; artık hepsi `fsx` ile süre sınırlıdır, `disk_changed`in "silindi mi" sorusu worker'a (`loader::reload`) taşındı; (2) `std::fs` çağrıları tokio çalışma iş parçacıklarında bloklanıyordu (takılı her okuma bir işçiyi kalıcı tutar; hepsi dolunca zamanlayıcı/watcher/soket de durur): okuma, yazma, dizin listeleme, dosya işlemleri, git tabanı, hex kaydı artık `fsx::off_thread` ile **kendi iş parçacığında** çalışır; (3) çıkışta tokio çalışma zamanının düşürülmesi bloklayan işleri sonsuza dek bekler → `Message::Exit` 1,5 sn sonra süreci zorla bitiren bir bekçi başlatır (oturum o zamana kadar yazılmıştır); (4) tek pencere soketi donmuş süreci "canlı" sanıyordu (yukarıda "Tek pencere"): başlatma sessizce çıkıyor, simge hiçbir şey yapmıyordu ve yalnızca yeniden başlatma çözüyordu; (5) oturum geri yüklemede erişilemeyen bir dosya tüm sekmeleri bekletiyordu: sekme başına 5 sn süre sınırı (`loader::restore_within`); süre aşılan, kaydedilmemiş işi olmayan sekme sessizce atlanır, **taslağı olan sekme taslakla (kirli) geri gelir**. Yazılan dosya sistemi hiçbir zaman boş bir arabellekle "geri yüklenmez".
  * *Sınırlar:* proje araması ve Ctrl+P dizini hâlâ tokio işçilerinde yürür (bağlantılı bir klasör çalışma alanı kökü ise orada takılabilir); oturum geri yükleme sırasında ulaşılamayan dosya sekmesi gerçekten atlanır (bildirim yok); gvfs'nin kendi bağlantı zaman aşımları (dakikalar) bizim denetimimizde değil. Sunucuda gerçekten boşalan dosya (kesik yazma) için bir yedek tutulmaz: yalnızca editördeki kopya korunur.
  * *Doğrulama:* gerçek pencerede FIFO ile ölü bağlantı taklidi (açılış bloklanır, pencere yine açılır, kapanış 0,1 sn) ve `SIGSTOP` ile donmuş ilk örnek (ikinci başlatma 1,6 sn'de kendi penceresini açar, üçüncüsü ona iletir).

- **Kaydederken sondaki boşlukları kırp** (ayar `trim_trailing_whitespace`, varsayılan **kapalı**; Ayarlar paneli "Trim on save", Preferences menüsü, palet "Preferences: Toggle Trim Trailing Whitespace on Save"). Kapalıyken dosya olduğu gibi yazılır. Açıkken `App::text_to_save` (hem `SaveTab` hem `SavePicked` yolu, yani Farklı Kaydet de) yazmadan *önce* buffer'ı `EditorState::trim_trailing_whitespace` ile temizler: satır sonundaki boşluk/tab ve diğer yatay boşluklar (NBSP, U+3000 vb.) tek bir `commit`'le kaldırılır, satır sonu karakterleri (LF/CRLF, VT/FF/NEL/LS/PS) asla silinmez. Dosyaya yazılan metin buffer'la birebir aynı kalır (disk özeti, "kaydedildi" durumu, geri alma tutarlı); işlem **bir geri alma adımıdır** (`Ctrl+Z` boşlukları geri getirir ve sekme tekrar kirli olur), imleç/seçimler `mapped_selections` ile, katlamalar ve bölünmüş görünümün ikinci bölmesi normal düzenleme yoluyla (`fold_plan`, `note_change`) izler. Kırpılacak bir şey yoksa metin, sürüm ve geçmiş değişmez. Durum çubuğu "Saved x — trimmed N lines" der. Maliyet yalnızca kaydederken ve yalnızca ayar açıkken O(satır); açılış süresine etkisi yok. **Markdown istisnası:** hedef dosya adı Markdown ise (`Lang::detect(path) == Markdown`; *yazılacak* ada bakılır, Farklı Kaydet `.txt` → `.md` yapabilir) `keep_breaks` açılır ve sert satır sonu olan satırlar olduğu gibi kalır: metinden sonra yalnızca boşluk karakterlerinden oluşan **2 veya daha fazla** boşluk *ve* ardından boş olmayan bir satır (`EditorState::is_hard_break`). Paragraf sonundaki (sonraki satır boş) ya da dosya sonundaki boşluklar anlamsız olduğundan kırpılır; tek boşluk, tab içeren artıklar (`\t  `) ve yalnız boşluktan oluşan satırlar da kırpılır. Kod çitleri ayrıca ele alınmaz (çit içinde de aynı kural). CRLF'de aynı.

Tasarım (`editor/state/split.rs`): belge `doc.state` tek bir `EditorState`tir (metin + geri-al geçmişi + *odaktaki* bölmenin görünümü); öteki bölme `Tab.split.mirror`, yani metnin O(1) klonunu (ropey düğümleri paylaşılır) ve kendi görünümünü tutan ikinci bir `EditorState`. Odak değişince iki görünüm `swap_view` ile **yer değiştirir**; böylece bul/git/durum çubuğu/geri-al gibi `doc.state` okuyan her kod, kullanıcının çalıştığı bölmeyi görür ve hiçbirinin bölmeden haberi olması gerekmez. Metni değiştiren üç yer (`commit`/`undo`/`redo`) bölme varken değişikliği (`Change`: konum, silinen, eklenen) kaydeder; `App::update` sonunda `Tab::sync_split` bunları aynaya `follow` ile **yeniden oynatır** ve aynanın imleç/katlamalarını aynı düzenlemeyle kaydırır (`map_through`, `fold_plan/fold_apply`). Kayıt yalnızca bölme açıkken tutulur (bölmesiz sekmede maliyet sıfır); kayıt taşar ya da metin bütünüyle değişirse (diskten yeniden yükleme) ayna baştan eşitlenir. Pasif eylemler (tekerlek, kaydırma çubuğu, minimap, katlama oku) odağı çalmaz ve doğrudan o bölmenin durumuna uygulanır; tıklama/yazma odağı o bölmeye alır. Ayırıcı sürüklenir (`SplitResize*`, ofset tabanlı). Bölme oturuma **yazılmaz** (yeniden başlatınca tek bölme), başlangıca hiçbir maliyeti yok. Sınama: `a_split_mirror_follows_every_edit_from_either_pane` (rastgele eylemler, iki bölme, 4000 tohum), `panes_keep_their_own_scroll_cursor_and_folds`, `a_split_tab_shows_one_text_in_two_panes_with_their_own_places`; gerçek pencerede `xdotool` ile doğrulandı. Not: geri-al, düzenlemenin yapıldığı yere gider; odaktaki bölme o yere kayar.
- **Dosya diyaloglarının başlangıç klasörü**: Aç (Ctrl+O), Farklı Kaydet, Klasör Ekle ve arama kapsamı diyalogları, son seçilen/kaydedilen dosyanın klasöründe açılır (`App::dialog_dir`, `session.json: last_dir`, yeniden başlatmada da korunur). Önce son seçim, yoksa etkin dosyanın klasörü, yoksa ilk çalışma klasörü; klasör silinmişse bir sonrakine düşer; hiçbiri yoksa masaüstü kendi "Recent" sayfasını gösterir. Diyalog iptali hatırlananı silmez. xdg-portal diyaloğunda gerçek pencerede doğrulandı.
- **Bölmelerin ad çubukları** (`tab_bar::pane_header`): her bölmenin üstünde 26 px'lik, VS Code'daki editör grubu sekmesi gibi bir çubuk var: dosya adı (kaydedilmemiş sekmede ilk satır), kirli işareti, bölmeyi kapatan ×. Odaktaki bölmeninki vurgulu (vurgu çizgisi + parlak yazı); çubuğa tıklamak o bölmeye odaklar (`FocusPane`), × o bölmeyi kapatıp *öteki* bölmenin görünümünü korur (`ClosePane`), sağ tık sekme menüsünü açar.
- **Sekmeleri sürükleyip yer değiştirme**: sekmeye *fare basılınca* (`TabPressed`) sekme etkinleşir ve sürükleme adayı olur; imleç 6 px'ten fazla oynarsa sürükleme başlar, bırakılınca (`TabDragEnd`) `TabSet::move_to_slot` ile taşınır. Sürüklerken sekmeler yer değiştirmez (genişlikleri farklı olduğundan canlı yer değiştirme titrer); sürüklenen sekme soluk görünür ve bırakma noktasında bir ekleme çizgisi (`tab_bar::Drag`, `slot_at`: komşu sekmelerin ortasına göre) çıkar. Şeridin ucuna yaklaşınca şerit kayar; şeritten çok uzağa çekmek, Esc ya da kaçan bir bırakma (`LEFT_DOWN`, mesajsız imleç aboneliğinde tutulur) sürüklemeyi iptal eder. Yeni sıra oturuma yazılır. **iced dersi:** `button` basışı yakalar, içine konan `mouse_area` ise *önce* çalışır ve basışı kendi alır; bu yüzden sekme gövdesi `button(mouse_area(...))`: üzerine gelme görünümü düğmeden, basış `mouse_area`dan gelir.
- **Önizleme sekmeleri (Sublime gibi)**: kenar çubuğunda bir dosyaya *tek* tıklamak onu italik başlıklı bir önizleme sekmesinde açar (`Tab.preview`); sonraki tek tıklama, bu sekmenin yerine (aynı sıraya) geçer. Sabitlenme: sekmeye ya da kenar çubuğundaki dosyaya çift tıklama (`DOUBLE_CLICK` 450 ms), sekmede herhangi bir düzenleme (kirli olan sekme hiç değiştirilmez; `App::update` sonunda kontrol edilir), bölme, bağlam menüsünden Aç, Ctrl+O / palet ile açma. Zaten açık bir dosyaya tıklamak yalnızca onu öne alır. Yükleme asenkron olduğundan niyet mesajla taşınır (`OpenedPreview` / `Opened`); iki tıklama yükleme bitmeden gelirse ikincisi sekmeyi sabitler. Önizleme durumu oturuma yazılmaz.
- **Apache yapılandırması** (`.htaccess`, `httpd.conf`, sanal konaklar, `.conf` içeriği Apache ise): eskiden INI dilbilgisiyle boyanıyor, `<IfModule>` bölümleri ve `Options -MultiViews` gibi satırlar hata sayılıp rastgele renkleniyordu. Şimdi `lexer::paint_apache`: satır başı yönerge adı, `<Bölüm args>` etiketleri, `%{DEĞİŞKEN}` / `$1`, `[BAYRAKLAR]`, `+/-Seçenekler`, desenler, URL'ler, modül adları, `on/off/all` ve `\` ile devam eden satırlar.
- **Dil algılama**: `.config` (web.config, app.config), `.xlf`, `.dtd`, `.nuspec` ... XML; kopya/şablon sonekleri soyulur (`sitemap.xml.old`, `phpunit.xml.dist`, `.htaccess.bak`, `index.php~`); adı bir şey söylemeyen dosyalar ilk baytlarına göre (`<?xml`, `<?php`, `#!/...`, `<!DOCTYPE html`) ve `.conf` dosyaları içeriğe göre (Apache / nginx) boyanır (`Lang::detect_with`). `.txt`/`.log` gibi düz metin adlarına dokunulmaz.

## 10. Derleme ve çalıştırma

```bash
export PATH=$HOME/.cargo/bin:$PATH
cargo run --release -- [KLASÖR|DOSYA]...   # klasör → workspace kökü, dosya → sekme
cargo test                                  # 186 test (Windows ikilisi: 181); başsız UI testleri target/ui-snapshots/*.png üretir
```

## 11. Performans (ölçülmüş)

Fedora 44, `cargo build --release`, 24 çekirdek; `VELOEDIT_TIMING=1` (süreç başlangıcından ilk `view()`'a, makine boştayken 6 koşu):

| Render arka ucu | İlk `view()` |
|---|---|
| wgpu (varsayılan) | **~82-90 ms** (≈70 ms GPU/yüzey başlatma) |
| tiny-skia (`ICED_BACKEND=tiny-skia`) | **~10 ms** |

Yük altında (derleme/test çalışırken) bu değerler ~1,5-2 kat çıkabiliyor.

Editör çekirdeği (`cargo test big_documents -- --nocapture`, 22 MB / 300 bin satır):

| İş | Süre |
|---|---|
| Tamponu yükleme | ~50 ms |
| 2000 × (tıkla + harf yaz) | ~10 ms toplam (~5 µs/tuş) |
| 400 imleç hareketi (PgDn / Shift+↓) | ~1 ms |
| 500 undo | ~1 ms |
| 60 satırı okuma (bir karelik) | ~0,1 ms |

16 MB / 210 bin satırlık belgede başsız çizim: kare başına ~22 ms (GPU'dan geri okuma dahil), ilk düzen ~120 ms (başsız renderer başlatması dahil).

* Release ikilisi **27 MB** (M1: 14 MB; fark ağırlıklı olarak 25 tree-sitter grameri; SQL'in tek başına +13 MB tuttuğu görüldüğü için SQL/C#/C++ lexer'e alındı). İlk view: wgpu ~81 ms, tiny-skia ~10 ms (M6'da değişmedi). `ldd`: yalnızca libc/libm/libgcc_s.

* Sidebar ve hex görünümü sanallaştırılmıştır; editör yalnızca görünen satırları çizer; palet en çok 12 satır.
* Gerçek ekranda doğrulanan: yalnızca M1'in ilk karesi ve M2/M3 ikilisinin açılışı (çökmeden, 1,5 sn). M3 editörünün gerçek klavye/fare davranışı başsız `iced_test` simülatörüyle (tıklama, yazma, Ctrl+Z, çift tıklama, tekerlek, minimap) sınandı, elle denenmedi.
